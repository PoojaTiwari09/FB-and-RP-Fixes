================================================================================
                    ROLE-BASED API ACCESS
================================================================================

MANAGER (alex.morgan@relanto.com)
├── Sales Engagement APIs ✓ (Can view all tasks)
├── Conversation Intelligence ✓ (Can see all calls & reviews)
├── Forecasting ✓ (Can access forecasts & boards)
└── Reports ✓ (Manager-level reports)

SALES_REP (sarah.chen@relanto.com)
├── Sales Engagement APIs ✓ (Can view own tasks)
├── Conversation Intelligence ✓ (Can see own calls)
├── Forecasting ✗ (Not typically available)
└── Reports ✗ (Limited reporting)

API STRUCTURE:
             
Request with Manager Token {{accessToken}}
    ↓
Backend Validates JWT & Extracts Role = "MANAGER"
    ↓
Routes decorated with @Roles('MANAGER', 'SALES_REP')
    ↓
Role matches → Allow Access ✓
    ↓
Return Data

Request with Sales Rep Token {{repAccessToken}}
    ↓
Backend Validates JWT & Extracts Role = "SALES_REP"
    ↓
Routes decorated with @Roles('MANAGER', 'SALES_REP')
    ↓
Role matches → Allow Access ✓
    ↓
Return Data (filtered by user's own records)

Request with Invalid Token or No Token
    ↓
JWT Validation Fails
    ↓
Return 401 Unauthorized ✗

================================================================================
                  VARIABLE PERSISTENCE FLOW
================================================================================

Postman Collection Variables (Persist for Entire Run):

1. baseUrl
   ├─ Initial: http://localhost:3002
   └─ Used: Every request's {{baseUrl}} placeholder

2. accessToken
   ├─ Set: After "Manager Login" test script
   ├─ Stored: JWT token string
   ├─ Used: All Manager API requests
   └─ Cleared: After logout (optional)

3. repAccessToken
   ├─ Set: After "Sales Rep Login" test script
   ├─ Stored: JWT token string (different from manager)
   ├─ Used: All Sales Rep API requests
   └─ Cleared: After logout (optional)

4. taskId
   ├─ Set: After "Create Task" test script
   ├─ Stored: Task UUID from response
   ├─ Used: In GET/PATCH/DELETE task requests
   └─ Example: /tasks/{{taskId}}/detail

5. periodId
   ├─ Set: After "Get Periods" test script
   ├─ Stored: Period UUID from response
   ├─ Used: In GET /periods/{{periodId}}/board
   └─ Example: /forecasting/periods/{{periodId}}/board

All variables available for subsequent requests in same run.
