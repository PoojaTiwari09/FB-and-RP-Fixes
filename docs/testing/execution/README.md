## Where to start

* **New to the repo:** read `version_knowledge.md` end-to-end, then `analysis_platform-core.md`, then the analysis file matching the module you'll work on.
* **About to smoke test:** start at `smoke_test_plan.md` Section 1.
* **Adding a feature or unblocking M04:** start at `implementation_changes.md` §C (Prisma unification) and §C5 (M04 TypeORM → Prisma).
* **Cursor / Codex / AI agent context bootstrap:** ingest `version_knowledge.md` + the relevant `analysis_*.md`. Together they describe the repository without further file scans.

## Audit scope honesty

This is a single-pass automated audit. It does **not** claim to have rewritten every module, removed every duplicate, or shipped every documented feature. It claims to have:

1. Built an accurate map of the repository as it exists today.
2. Identified and fixed the 5 critical compile blockers in `apps/api`.
3. Normalized the corrupted unified Prisma schema so `prisma validate` passes.
4. Documented every other gap with a severity rank and an explicit follow-up step.
5. Provided a smoke plan that lets a fresh engineer prove the platform is operational.

The follow-up work that remains (TypeORM → Prisma migration for M04, real event publisher, RLS migration, M03 Supabase cutover, frontend vendored-app integration) is fully scoped in `implementation_changes.md`. Pick those up one at a time.
