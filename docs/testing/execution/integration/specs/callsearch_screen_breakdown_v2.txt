Revenue Intelligence UI · Sales Manager
================================================================================

Screen Name:
  Call Search

Route:
  /search
  /search?tab=all             → All tab
  /search?tab=calls           → Calls tab (default active)
  /search?tab=emails          → Emails tab

Purpose of Screen:
  Central search & discovery screen for sales calls and emails across the
  organization. Enables managers and reps to filter, find, and analyze recorded
  calls/emails using a combination of team, rep, stage, participants, keywords,
  topics, trackers, scorecards, and call-type filters. Applied filters are shown
  as removable chips with a "Clear" link. Results can be exported to CSV (with
  field selection via modal) or saved as a persistent stream (with notifications
  and sharing). Clicking a result opens a call detail drawer with recording,
  next steps, key highlights, conversation highlights (clickable moments),
  full transcript, and AI Q&A.

2. GET /api/calls/search
--------------------------------------------------------------------------------

Purpose:
  Fetch filtered + paginated call/email list for the results table,
  the chart data, and the tab counts. Called on mount and on every
  filter / sort / tab / pagination change.

Request Query Params:
  - page              (number, default: 1)
  - size              (number, default: 20)
  - tab               (string: "all" | "calls" | "emails")
  - team              (string: "west" | "east" | "central" | "all")
  - rep               (string: repId or "all")
  - stage             (string: stage value or "all")
  - participants      (string: free-text)
  - wordsOrPhrases    (string: keyword/phrase)
  - phraseMatchType   (string: "contains" | "mentioned_by_any" | "said_anytime")
  - topics            (string: topic value or "all")
  - trackers          (string: tracker value or "all")
  - scorecardResult   (string: "all" | "excellent" | "good" | "average" |
                                "needs_improvement")
  - callTitle         (string: free-text)
  - callType          (string: "all" | "internal" | "customer")
  - sortBy            (string: "date" | "call_duration" | "deal")
  - sortOrder         (string: "asc" | "desc", default: "desc")
  - dateFrom          (string: ISO date, optional)
  - dateTo            (string: ISO date, optional)
  - chartGranularity  (string: "days" | "weeks" | "months" | "quarters",
                        default: "weeks")

================================================================================
API ENDPOINTS IMPLEMENTED
================================================================================

The following endpoints were utilized to integrate the frontend components 
with the backend services:

1. GET /api/filters/options
   - Purpose: Fetches the available filter options to populate the sidebar dropdowns 
     (Teams, Reps, Stages, Topics, Trackers, Scorecards).

2. GET /api/calls/search
   - Purpose: Performs the main search for calls and emails.
   - Query Params: tab (all|calls|emails), sortBy, sortOrder, and all applied filters.
   - Returns: Paginatable list of call/email results, chart data, and total metadata.

3. GET /api/calls/:callId
   - Purpose: Fetches comprehensive detail for a specific call (transcript, 
     timeline, next steps, highlights) used to populate the Call Detail Drawer.

4. POST /api/calls/ai-ask
   - Purpose: Submits a custom question about a specific call to the AI engine 
     within the Call Detail Drawer.
   - Body: { callId, question }
   - Returns: AI-generated answer based on the call context.

5. POST /api/calls/export
   - Purpose: Triggers an asynchronous CSV export of the currently filtered search results.
   - Body: { filters, fields }
   - Returns: A jobId to track the async export task.

6. POST /api/streams
   - Purpose: Saves the currently applied search filters as a persistent "Stream" 
     with specific notification and sharing preferences.
   - Body: { name, filters, notifications, sharing }
   - Returns: The created streamId.
