Screen Name:
Smart Call – Live Assist

Route:
/smart-call  (or /engage/smart-call/{contactId})

Purpose of Screen:
Smart Call is an AI-powered live call assistant that guides sales reps in real-time during calls. The rep selects a contact, initiates a Smart Call session, gets live AI coaching, competitor intelligence, suggested responses, and intent signals during the call. After the call ends, a detailed Call Summary with performance scores, key moments, missed opportunities, and improvement suggestions is generated automatically.

Flow:
1. Rep clicks "Smart Call" anywhere in the app (or navigates to /smart-call)
2. Contact Selection screen — rep searches and selects a contact to call
3. Smart Call Pre-Call screen — AI briefing, feature overview, screen sharing consent
4. Live Session screen — real-time AI guidance, overlay mode available
5. End Session confirmation modal
6. Call Summary screen — post-call analysis and scoring

- Use Signals tab in overlay (intent signals)
- Use Log tab in overlay (call log/transcript)
- Minimize or close overlay widget

- End session ("End Session" → confirmation modal)
- Cancel end ("Cancel" in confirmation modal)

- View Call Summary: Performance Snapshot, AI Summary, Key Moments, Missed Opportunities, Suggested Improvements, Conversation Timeline
- View Full Transcript (footer button)
- Practice Again (footer button — restart Smart Call flow)
- Back to Dashboard (footer button)

4. LIVE AI COACHING — Direct Browser API Calls (Groq + OpenRouter)
================================
Purpose:
Real-time AI coaching during the Live Session is powered by direct browser-to-API calls — no backend relay needed.
The rep clicks "Start AI Assist" to trigger browser screen/tab audio capture (getDisplayMedia). Audio is chunked
every 7 seconds, transcribed, and fed to a coaching LLM. Deep analysis runs every 30 seconds via a separate model.

If the rep has not configured API keys, the session falls back to mock simulation data automatically.

API Keys are stored in browser localStorage (never sent to the backend):
  - Groq key: sc_groq_key
  - OpenRouter key: sc_openrouter_key

--- 4a. POST https://api.groq.com/openai/v1/audio/transcriptions ---
Purpose: Transcribe 7-second audio chunks captured from the rep's active call tab.
Model: whisper-large-v3
Auth: Bearer {groq_api_key}

Sample Request (multipart/form-data):
  file:            audio.webm (Blob, audio/webm;codecs=opus)
  model:           whisper-large-v3
  language:        en
  response_format: json

Sample Response:
{
  "text": "So Sarah, I wanted to walk you through the ROI we've seen with similar customers..."
}

--- 4b. POST https://api.groq.com/openai/v1/chat/completions ---
Purpose: Generate tactical live coaching events from the accumulated transcript (runs after each transcription chunk).
Model: llama-3.1-8b-instant
Auth: Bearer {groq_api_key}
Config: response_format: { type: "json_object" }, temperature: 0.3, max_tokens: 1200

System Prompt instructs the model to return a single JSON object. Frontend maps fields to these live event types:
  LIVE_GUIDANCE, SUGGESTED_RESPONSES, COMPETITOR_INTELLIGENCE, INTENT_SIGNALS, TALK_RATIO

Sample LLM JSON Output (coaching):

================================
Validations:
================================
- contactId: required on session start; must be a valid contact in the system
- taskId: optional on session start (pass if called from a task context)
- integration: optional; must be ZOOM | MEET | TEAMS | OTHER if provided
- generateSummary: defaults to true on session end
- Search query (contact selection): min 1 character; debounce 300ms
- Session cannot be started if another session is already LIVE for the same rep

================================
Dynamic Data:
================================
- Contact Selection screen: contact list — from contacts API (lazy loaded, search-driven)
- Pre-Call screen: contact name, company, AI briefing, key objections, deal stage — from pre-call-brief API
- Pre-Call screen: supported integrations (Zoom/Meet/Teams) — from pre-call-brief API
- Live Session header: contact name, company, task title — from session start response
- Live Session left panel: ALL content streamed in real-time via WebSocket:
    * Live Guidance (stage + next suggestion)
    * Suggested Responses (4 cards)
    * Competitor Intelligence (multiple competitor blocks)
    * Conversation Summaries (rolling segments with highlighted keywords + tags)
- Live Session right panel: ALL content streamed via WebSocket:
    * Intent & Risk Signals (label, value, severity, color)
    * Talk Ratio (rep %, customer %)
    * Conversation Metrics (interruptions, pace, WPM, questions)
- Overlay Widget: all content from OVERLAY_UPDATE WebSocket event:
    * Confidence score %, context summary, action suggestion
    * Suggested response, strategic tip + script
    * Competitor intelligence (multiple)
    * Coach/Signals/Log tabs
- Session timer: client-side, counts up from 0:00 on session start
- "Overlay Active" button state: toggles green when overlay is enabled
- Call Summary: all sections from summary API
- Full Transcript: from transcript API (loaded on "View Full Transcript" click)

Notes:
================================
- The Contact Selection screen is the entry point when Smart Call is accessed independently (not from a task). If launched from a task's "Smart Call" button, skip Contact Selection and go directly to the Pre-Call screen using the task's linked contact.
- Live AI coaching (API #4) uses direct browser calls to Groq (Whisper + LLaMA) and OpenRouter (DeepSeek). No WebSocket or backend relay is involved for the live coaching data path.
- Rep must click "Start AI Assist" to trigger browser screen/tab audio capture (getDisplayMedia). The button is disabled once capturing starts and shows "AI Active".
- If no Groq API key is set, the session automatically falls back to mock event simulation so the UI is always functional for demo/testing.
- API keys (Groq + OpenRouter) are entered via the "Set Up API Keys" button on the Contact Selection screen. Keys are stored in browser localStorage only — never sent to the backend or committed to source control.
- The Overlay Widget is a fixed-position floating panel (top-right corner) — position should be saved in local/session state so it doesn't reset on content updates.
- Overlay confidence score (e.g. "88%") represents AI confidence in the current context detection — update on each OVERLAY_UPDATE event.
- Multiple competitor blocks can appear simultaneously in both the main Competitor Intelligence section and the overlay Coach tab.
- Conversation Summaries in the right panel update in rolling fashion — new segments prepend to the top.
- Highlighted keywords in summaries ("pricing" in orange, "ROI" in blue) are AI-tagged — the backend must return the keyword + color in the CONVERSATION_SUMMARY event.
- Key Moments types on Call Summary: OBJECTION (yellow), INTEREST_SIGNAL (green), MISSED_OPPORTUNITY (red) — frontend should color-code cards based on type.
- "Missed Opportunities" is a separate section from "Suggested Improvements" — both must be returned from the summary API.
- "Practice Again" restarts the entire Smart Call flow from the Contact Selection screen (or Pre-Call if context is preserved).
- Screen sharing permission is a browser-level API (getDisplayMedia) — no backend involvement. The browser will prompt the user to select a screen/tab. Only audio tracks are used; video tracks are dropped immediately.
- All timestamps in transcript and timeline are in MM:SS format (display); store as seconds integer on the backend.
- Session timer in the header is purely client-side (no backend sync needed).
- Focus Mode: hides the right analytics panel to show only the left guidance panel — pure frontend UI toggle, no API needed.
- taskTitle in the session start response is displayed in the Live Session header as the call/task title.
